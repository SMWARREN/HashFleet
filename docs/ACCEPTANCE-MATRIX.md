## Acceptance boundary

The app has direct real-miner evidence, not only fixtures: LIVE-1 through LIVE-3 exercise its shipped native navigation, foreground polling and manual compatibility action. Controlled HTTP fixtures are retained for safe, repeatable failures and confirmation gates that must not be tested destructively on user hardware. They supplement rather than replace the real successful path.

Coverage boundaries above must not be silently converted to “passed” by aggregate suite totals. All-provider success, every physical model, physical fault/tuning/OTA safety, on-phone UI permissions and complete accessibility certification remain outside verified acceptance. The concrete changed-output paths R13/R21/R22 now have native UI assertions rather than inspection-only evidence. Traceability maps outputs to checks, but does not mean every possible state or hardware permutation was tested.
