# Model-aware capability contract (implementation handoff)

Implementation clarification after acceptance: this document began as a worker handoff, not a claim that every proposed gate shipped. Native settings use reported fields for drafts and uncertainty notes, but missing fields or an absent check do not disable manual entry. They are not a model-based allowlist or proof of write support. ASIC references can be refreshed deliberately from tuning; that is a read-only reference action, separate from the two-endpoint compatibility check. Every write still passes review and confirmation. See [requirement-to-check observations](ACCEPTANCE-MATRIX.md) for tested behavior and remaining gaps.

Root coordinates builds and device access. Only GET Info and ASIC are authorized for physical verification. No automatic writes, presets, network scans or broad endpoint probing.

Core worker owns new Sources/HashFleetCore/MinerCapabilities.swift:
- public enum MinerProbeStatus: Hashable, Sendable: notChecked, supported, unsupported(statusCode: Int), failed(message: String).
- public struct MinerCapabilityReport: Hashable, Sendable with public info: MinerInfo?, asic: JSONValue?, infoStatus: MinerProbeStatus, asicStatus: MinerProbeStatus, checkedAt: Date; public initializer accepting these fields, default nil/notChecked and Date().
- public struct MinerCapabilityProbe: Sendable, init(client: MinerAPIClient), func check() async throws -> MinerCapabilityReport.
- check sends ONLY one GET .info and one GET .asic, using injected client/session. Cancellation must throw, not become unsupported. 404/405/501 are unsupported. Authentication, throttling, 500, transport errors and malformed JSON are failures, never hardware non-support. Return partial success. No response-body secrets in summaries.
- Validate JSON object shape; empty/unrecognized payload is failed/unrecognized, not a valid device or unsupported model. Document minimal recognized keys and tests. Do not require one named ASIC or board.
- Missing firmware fields mean Not reported, not proof of unsupported hardware. Do not infer supported settings or electrical safety from model name alone.

App/Store/MinerCapabilitiesStore.swift integrates with FleetStore. It exposes @MainActor @Observable MinerCapabilitiesStore reports: [UUID: MinerCapabilityReport], checking: Set<UUID>, func check(device: MinerDevice, isDemo: Bool) async. Store created once as FleetStore.capabilities. Fresh checks replace the whole previous report. Demo checks are no-ops: no network and no fabricated probe result. The UI may describe sample identity with checking disabled. No raw persisted capability data or extra shared widget data.

UI worker owns MinerDetailView.swift, MinerSettingsView.swift, MinerTuningSection.swift and NEW MinerCompatibilityView.swift. Entry point MinerCompatibilityView(device:store:), use store.capabilities.reports[device.id] and .checking; manual .task(id:) or Task owned by view to call check. No initial automatic real requests. Friendly one-screen Info/ASIC states, firmware/board/ASIC identity, explicit Check compatibility button, retry, partial failures. Hide verbose data behind disclosures. Settings use the most recent reported fields from ordinary telemetry or a successful compatibility read. Unknown/missing fields must say Not reported / check compatibility rather than falsely Unsupported. Advanced JSON and reviewed manual entry remain available with existing warnings. Never assume a reported field guarantees write support. Tuning uses device-reported ASIC options as references, never safe ranges/presets. Avoid blocking existing demo test navigation or changing IDs.

Independent tests worker owns Tests/HashFleetCoreTests/MinerCapabilityTests.swift (discover actual test folder first) and optionally AppTests/MinerCapabilityStoreTests.swift after root store contract exists. No other files or builds. Cover HTTP status distinctions, partial success, malformed shape, cancellation, exactly Info/ASIC paths only, model diversity and missing fields. Use isolated URLProtocol, never physical devices.
